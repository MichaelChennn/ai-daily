# X/推特获取方式调研

> 对应 issue #16。调研日期 2026-10-25。所有结论以下列一手来源在该日的内容为准，X 的价格和条款变动频繁，引用前请复查。

## 结论

**不存在“免费、不用 cookie、不违反 X 服务条款”的方案。** 建议把“抓取 X/推特”放进 map 的 Out of scope。

- 合规的路只有官方 X API，现在只有按量付费（Pay-Per-Use），读一条帖子 $0.005，没有给新开发者的免费档。
- 所有免费路线（RSSHub 的 cookie 模式、Nitter、自写爬虫）都要登录账号的 cookie 或 session，并且违反 X 服务条款里禁止爬取的条款。Nitter 在 2026-08 收到 X 的律师函，仓库已于 2026-10-09 归档。
- 第三方付费 API（TwitterAPI.io、SocialData 等）便宜，但都声明与 X 无关，数据来源不公开，对本项目而言等于把违约风险转包出去，不算合规。

如果以后愿意付费，官方 API 抓 20 个账号的成本大约每月 $15 左右（估算见下文），技术上可行，但它会给“确定性抓取、零成本跑在 GitHub Actions 上”的设定引入付费密钥。

更划算的做法：这些博主转发的内容大多来自有 RSS 的一手来源，直接把这些来源加进 `sources.yaml`，就能覆盖 X 上的大部分信号（名单见文末）。

## 1. 官方 X API

### 当前计费模式

- X API v2 现在写的是“uses pay-per-usage pricing with no subscriptions”：在 Developer Console 里预充 credits，按请求扣费，无合约、无最低消费。来源：[docs.x.com — Pricing](https://docs.x.com/x-api/getting-started/pricing)、[About the X API](https://docs.x.com/x-api/getting-started/about-x-api)。
- 读取价格（每个返回的资源）：Post $0.005；User、DM、followers/following $0.010；Likes/mutes/blocks $0.001；Lists/Spaces/Communities/Notes $0.005。来源同上。
- “Owned Reads”（读自己账号的数据，如认证用户自己的 `/2/users/{id}/tweets`）$0.001，2026-04-20 起生效。读**别人**的时间线不享受这个价。来源：[X API Changelog 2026-04-16](https://docs.x.com/changelog)。
- 按量付费每个计费周期上限 300 万条 Post 读取，超过要走 Enterprise。同一资源在 24 小时 UTC 窗口内去重、不重复收费（文档称“soft guarantee”）。来源：[Pricing](https://docs.x.com/x-api/getting-started/pricing)。
- 读用户时间线的接口 `GET /2/users/:id/tweets`：10,000 次/15 分钟/app，900 次/15 分钟/user。来源：[Rate limits](https://docs.x.com/x-api/fundamentals/rate-limits)。

### 档位变迁（Changelog 原文，按时间）

来源均为 [X API Changelog](https://docs.x.com/changelog)：

| 日期 | 变化 |
|---|---|
| 2023-06-26 | Basic、Pro 档移除 Follows 等接口（当时档位为 Free / Basic / Pro / Enterprise） |
| 2025-08-22 | Free 档移除 like、follow 接口 |
| 2025-10-20 | Pay-Per-Use 封闭试点，$0.005/Post Read，$0.01/User Read |
| 2026-02-06 | Pay-Per-Use 正式上线；“Public Utility Apps continue to receive free scaled access”；近期活跃的 Legacy Free 用户迁到 Pay-Per-Use 并获一次性 $10 券；Basic、Pro 对现有订阅者保留，可选择迁移 |
| 2026-04-16 | 新价格：Owned Reads $0.001，发帖 $0.015，带 URL 的帖子 $0.20 |
| 2026-10-02 | 一次性激励：绑卡送 $20，首次自动充值匹配最多 $50，credits 3 个月过期 |

- **免费档**：Changelog 里 Free 档在 2026-02-06 后只剩“Public Utility Apps”（需 X 认定的公益类应用）。官方定价页已不再列出 Free 档。新开发者只能用 Pay-Per-Use 加一次性赠送额度。
- **Basic（$200/月）、Pro（$5,000/月）**：官方文档只说保留给现有订阅者。第三方报道称 Basic 在 2026-06-01 后被强制迁移、Pro 在 2026-09-01 后被迁移（[Blotato](https://www.blotato.com/blog/twitter-api-pricing)），这两个日期**没有在 X 官方页面上找到**，仅供参考。对新项目没有影响：新开发者反正订不到。

### 哪一档能读用户时间线

Pay-Per-Use 就能读 `GET /2/users/:id/tweets`，按返回的 Post 计费。不存在“免费能读别人时间线”的档。

### 本项目的成本估算（推算，不是官方数字）

假设 20 个账号，平均每个每天 5 条原创帖（排除回复和转推），用 `since_id` 增量拉取，每条只计费一次：
20 × 5 × $0.005 = $0.50/天，约 **$15/月**。用户 ID 只查一次，缓存下来（$0.01/次，可忽略）。活跃账号多发几倍，费用就跟着翻几倍。

### 合规与风险

合规；按官方 API 使用不会因为“抓取”被封号，但要遵守 Developer Agreement。需要在 GitHub Actions 里保存 Bearer Token，并且要保证账户里有余额。

## 2. RSSHub 的 Twitter 路由

来源：RSSHub 源码 [`lib/routes/twitter/namespace.ts`](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/twitter/namespace.ts)、[`lib/routes/twitter/user.ts`](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/twitter/user.ts)。

- 路由：`/twitter/user/:id/:routeParams?`（User timeline）。`requireConfig` 列出 `TWITTER_AUTH_TOKEN`，或 `TWITTER_CONSUMER_KEY` + `TWITTER_CONSUMER_SECRET`。
- 认证方式三种：
  1. `TWITTER_AUTH_TOKEN`：“a comma-separated list of `auth_token` cookies of logged-in Twitter Web”，即**登录账号的 cookie**，RSSHub 用它调网页版内部 API。官方文档把它标为推荐方式。
  2. 用户名 + 密码 + TOTP：已划掉，原文“This no longer works since mobile client attestation has been implemented in October 2025”。
  3. `TWITTER_CONSUMER_KEY/SECRET`：调用官方“Pay-Per-Use developer API”，也就是第 1 节的付费 API。
- **要 cookie 吗**：免费用法（方式 1）要。不要 cookie 的用法（方式 3）要付费。
- **违反 ToS 吗**：方式 1 违反（见第 5 节条款）。方式 3 不违反。
- **封号风险**：方式 1 高。用 cookie 的账号会被 X 的反自动化系统识别，账号被锁或封禁很常见，这正是 RSSHub 支持填多个 token 轮换的原因。

## 3. Nitter

来源：[zedeus/nitter README](https://github.com/zedeus/nitter)、GitHub API（`archived: true`，`pushed_at: 2026-10-09T21:08:08Z`）、[Instances wiki](https://github.com/zedeus/nitter/wiki/Instances)、仓库 [`tools/`](https://github.com/zedeus/nitter/tree/master/tools)。

- **项目状态**：README 原文：“On 24 August 2026, cease and desist letters were sent by X Corp. demanding a permanent takedown of Nitter instances and the project's repository.” 2026-10-10 更新：作者在寻求资金和法律帮助。仓库已于 **2026-10-09 归档（只读）**。
- **认证**：Nitter 用“Twitter's unofficial API”。部署时要挂载 `sessions.jsonl`，内容是真实账号登录得到的 `auth_token` 和 `ct0` cookie，由仓库里的 `tools/create_session_*.py` 生成。`create_session_curl.py` 已标 DEPRECATED，原文“X now requires a castle token generated by client-side JavaScript during the login flow”，只能用浏览器脚本登录。所以**需要账号 cookie**。
- **公共实例**：wiki（2026-09-11 最后编辑）列出 7 个明网实例，标记都是在线，但这是社区维护的表，状态不一定准确。README 还说 RSS 是“instance-specific, often disabled due to abuse”。在收到律师函的背景下，公共实例随时可能下线，不能当稳定来源。
- **违反 ToS 吗**：违反。**封号风险**：自建时用于 session 的账号风险高；用别人的公共实例，风险落在实例运营者身上，但可用性没有保证。

## 4. 第三方付费服务

| 服务 | 价格 | 与 X 的关系 | 数据来源 |
|---|---|---|---|
| [TwitterAPI.io](https://twitterapi.io/pricing) | $0.15/1000 条，新号最多 $1 免费额度（31 天过期） | “independent third-party service. Not affiliated with, endorsed by, or sponsored by X Corp.” | 页面未说明 |
| [SocialData](https://socialdata.tools/) | $0.20/1000 条，无免费档 | 声明与 X Corp 无关 | “various sources”，未具体说明 |

- 价格比官方 API 便宜约 25–30 倍，也不需要我们自己提供 cookie。
- 但它们不是 X 授权的接口，数据显然来自爬取或账号池。X 服务条款同时追究“induce or knowingly facilitate”违约的人（见下节），使用这类服务不能算合规。服务本身也可能随时被 X 封掉，稳定性没有保证。Apify 等平台上的 Twitter scraper 同理。

## 5. X 服务条款的相关条款

来源：[X Terms of Service](https://x.com/en/tos)，生效日期 **2026-10-09**。

- 第 4 节“Misuse of the Services”：禁止“by any means (automated or otherwise)”在 X 公布的接口之外访问服务；“crawling or scraping the Services in any form, for any purpose without our prior written consent is expressly prohibited.” 还禁止绕过、操纵或禁用系统，禁止“work around any technical limitations”。
- 违约金条款：24 小时内“requesting, viewing, or accessing more than 1,000,000 posts”，按“$15,000 USD per 1,000,000 posts”赔偿（EU/UK 版为 €15,000）；违约者以及引诱或明知而协助者承担连带责任。
- X 可以因违反条款暂停或终止账号。

我们的量远到不了 100 万条，违约金条款实际上碰不到，但“禁止爬取”一条与数量无关。

## 6. 各方案对比

| 方案 | 免费 | 要 cookie | 违反 ToS | 封号风险 | 稳定性 |
|---|---|---|---|---|---|
| 官方 X API（Pay-Per-Use） | 否（约 $15/月） | 否 | 否 | 无 | 高 |
| 官方 Free（Public Utility Apps） | 是 | 否 | 否 | 无 | 需 X 审批，本项目不太可能拿到 |
| RSSHub + `TWITTER_AUTH_TOKEN` | 是 | **是** | **是** | 高 | 低 |
| RSSHub + consumer key | 否 | 否 | 否 | 无 | 高（就是官方 API） |
| Nitter（自建或公共实例） | 是 | **是**（自建） | **是** | 高 | 极低，项目已归档 |
| TwitterAPI.io / SocialData 等 | 否（很便宜） | 否 | 协助违约，不合规 | 服务可能被封 | 中低 |
